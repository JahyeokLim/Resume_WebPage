## 2026-07-27 — Django 프로젝트 초기 구현

### 환경 구성
- `python3-venv`가 설치되어 있지 않아 가상환경 생성 대신 `pip install --user`로
  Django 5.2, Pillow를 설치함 (sudo 권한이 없는 환경이라 시스템 패키지 설치는 보류).
- Django 프로젝트 `config`를 저장소 루트에 생성, 앱 3개 생성: `profiles`, `projects`, `contact`.

### 데이터 모델
- **profiles 앱**
  - `Profile`: 이름/직함/한줄소개/자기소개/사진/이메일/거주지/GitHub·LinkedIn 링크/이력서 PDF.
    모든 텍스트 필드는 `_ko`/`_en` 쌍으로 저장하고, 현재 언어에 따라 값을 반환하는
    `name`, `role` 등의 프로퍼티를 통해 템플릿에서는 언어 구분 없이 사용하도록 함.
  - `TimelineEntry`: 경력/학력 타임라인 항목 (분류, 기간, 설명, 정렬 순서).
  - `SkillCategory` / `Skill`: 기술 스택을 카테고리별로 묶어서 관리.
- **projects 앱**
  - `Project`: 제목/요약/개요/역할/아키텍처 설명(다국어), 기간, 기술 스택(쉼표 구분 태그),
    커버 이미지, 아키텍처 다이어그램 이미지, slug.
  - `visibility` 필드(`full` / `abstracted`)로 PRD의 "사내 보안 프로젝트는 추상화하여 공개"
    요구사항을 반영. 추상화 공개로 설정한 프로젝트는 상세/목록 페이지에 "추상화 공개" 배지가 표시됨.
    실제 추상화(회사명 삭제 등)는 Admin에서 내용을 입력하는 사람이 직접 수행.
  - `ProjectMedia`: 프로젝트에 첨부하는 이미지/동영상(유튜브 등 외부 링크) 여러 개를 관리.
- **contact 앱**
  - `ContactMessage`: 문의 폼으로 들어온 이름/이메일/메시지를 저장.

### 관리자(Admin) 구성
- 세 앱 모두 Django Admin에 등록. `Profile`은 싱글턴으로 취급하여 이미 하나 있으면
  추가 생성이 안 되도록 `has_add_permission`을 오버라이드.
- `ProjectMedia`는 `Project` 편집 화면에서 인라인으로 함께 추가/수정 가능.
- 방문자용 로그인 화면은 별도로 만들지 않고, 푸터의 작은 "Admin" 링크 → Django 기본
  로그인 화면(`/admin/`) → 로그인 후 Admin에서 데이터 수정하는 구조로 결정
  (PRD에도 반영: 일반 방문자는 로그인 절차 없이 콘텐츠만 열람).

### URL 구조 및 다국어(i18n)
- `django.conf.urls.i18n.i18n_patterns`를 사용해 모든 페이지가 `/ko/...`, `/en/...`
  형태의 언어별 URL을 가지도록 구성. 언어 선택은 Django 기본 `set_language` 뷰로 처리.
- `config/urls.py`에 `profiles`, `projects`, `contact` 앱의 URL을 연결.
- 개발 중에는 `DEBUG=True`일 때 업로드된 이미지/PDF(`MEDIA_ROOT`)를 Django가 직접 서빙하도록 설정.

### 화면 구현

  - `profiles/home.html` — 프로필 히어로, 경력/학력 타임라인, 기술 스택, 대표 프로젝트 3개, 이력서 PDF 다운로드 버튼.
  - `projects/project_list.html` — 전체 프로젝트 카드 목록 (기술 태그 표시).

  - `contact/contact.html` — 이름/이메일/메시지 문의 폼.
- 다크모드는 CSS 커스텀 프로퍼티(`--bg`, `--ink` 등)를 `:root`에 정의하고
  `prefers-color-scheme`와 `data-theme` 속성으로 오버라이드하는 방식. 테마 토글 버튼을
  누르면 JS가 `data-theme`을 바꾸고 `localStorage`에 저장해 재방문 시 유지되도록 함.

## 2026-07-27 — 한/영 번역 파일(locale) 추가

- 언어 전환 버튼을 눌러도 `{% translate %}`로 감싼 UI 문구들이 영어로 안 바뀌는
  문제 확인 → 원인은 `locale/` 디렉터리 자체가 없어서 번역 데이터가 전혀 없었기 때문.
- 이 환경에는 GNU gettext 도구(`msguniq` 등)가 설치되어 있지 않아 표준
  `python manage.py makemessages`/`compilemessages`를 쓸 수 없었음.
  대신 순수 파이썬 라이브러리 `polib`을 `pip install --user`로 설치하고,
  템플릿에서 번역 대상 문자열을 추출한 뒤 `locale/en/LC_MESSAGES/django.po`를
  직접 작성 → `polib`으로 `.mo`까지 컴파일하는 스크립트로 처리.
- 사이트 UI 고정 문구(홈/프로젝트/문의, 경력·학력, 기술 스택, 버튼 문구 등) 약 30여 개
  번역 등록. **주의**: Admin에서 입력하는 실제 콘텐츠(이름, 소개글, 프로젝트 설명 등)는
  애초에 모델에서 `_ko`/`_en` 필드로 분리되어 있어 이 번역 파일과는 무관하며,
  각 언어 필드에 직접 입력해야 함.

## 2026-07-27 — 관리자용 "편집" 메뉴, 로그아웃, 문의함(Inbox) 기능 추가

### 편집 진입점을 헤더로 이동
- 기존에는 푸터에만 작은 "Admin" 링크가 있었는데, 로그인한 관리자에게는 상단
  메뉴에서도 편집 화면으로 바로 갈 수 있도록 개선.
- `templates/base.html`에서 `request.user.is_staff`가 참일 때만 상단 메뉴에
  **편집**(Django Admin으로 이동) 버튼과 **로그아웃** 버튼을 노출. 로그인 진입점
  자체는 기존처럼 푸터의 "Admin" 링크 → `/admin/login/` 그대로 유지.
- 로그아웃은 Django Admin이 기본 제공하는 `admin:logout` 뷰를 POST 폼으로 호출
  (GET 링크가 아닌 폼으로 만든 이유: Django 로그아웃 뷰가 POST를 요구함).

### 문의 방식 변경: 이메일 발송 → 사이트 내 "문의함"
- 원래는 문의 폼 제출 시 `send_mail()`로 네이버 메일 앞으로 이메일을 보내려고
  SMTP 연동(환경변수로 네이버 계정 정보 관리) 작업을 시작했으나, 논의 중 방향을
  바꿔 이메일 발송 자체를 없애고 "관리자만 보는 문의함" 방식으로 결정.
  → SMTP 관련 설정(`config/settings.py`의 `.env` 로더, `NAVER_EMAIL_*` 설정)은
  전부 되돌림. `.env`/`.env.example` 파일도 삭제.
- `contact/views.py`에서 `send_mail` 호출 제거. 문의 폼은 이제 DB 저장만 수행.
- 관리자 전용 뷰 2개 추가 (`@staff_member_required`로 보호 — 비로그인 시
  `/admin/login/`으로 자동 리다이렉트):
  - `contact:inbox` (`/contact/inbox/`) — 받은 문의 목록. 안 읽은 항목은
    ● 표시, 읽은 항목은 ○ 표시.
  - `contact:inbox_detail` (`/contact/inbox/<pk>/`) — 문의 상세 내용을 열람하면
    자동으로 `is_read=True`로 갱신.
- `contact/context_processors.py`를 새로 만들어 로그인한 스태프에게만
  `unread_inbox_count`(안 읽은 문의 개수)를 모든 템플릿에 전달하도록 설정
  (`config/settings.py`의 `TEMPLATES.OPTIONS.context_processors`에 등록).
- 헤더에 이모지가 아닌 **선(stroke)으로만 그린 인라인 SVG 편지봉투 아이콘**을
  추가하고, 안 읽은 문의가 있으면 아이콘 우측 상단에 개수 배지를 표시.
  로그인 상태에서만 보이고, 로그아웃 상태/익명 방문자에게는 아이콘 자체가 없음.
- 번역 파일에 문의함 관련 문구(Inbox, Message 등) 추가.

### 확인한 사항
- 로그인 → 헤더에 편집/로그아웃/문의함 아이콘 노출 확인.
- 문의 폼 제출(비로그인 상태) → DB에 정상 저장, 문의함 배지 카운트가 1 증가.
- 문의 상세 페이지 열람 → 읽음 처리되고 배지 카운트가 다시 감소하는 것 확인.
- 로그아웃 → 편집/로그아웃/문의함 아이콘이 다시 사라지고, `/contact/inbox/`
  직접 접근 시 로그인 페이지로 리다이렉트되는 것 확인.

## 2026-07-27 — 로그인 후 이동 경로 변경, 프로젝트 목록에 썸네일·기간 추가

### Admin 로그인 후 곧장 Admin 대시보드로 넘어가던 것 개선
- 기존에는 푸터의 "Admin" 링크로 로그인하면 Django Admin 대시보드("사이트 관리" 화면)로
  바로 진입해서, 일반적인 사이트 탐색 흐름과 단절되는 느낌이 있었음.
- 푸터 "Admin" 링크를 `/admin/` → `/admin/login/?next=` + 사이트 홈 URL로 변경.
  이제 로그인에 성공하면 Admin 대시보드가 아니라 사이트 홈으로 돌아오고,
  이후 필요할 때 헤더의 **편집** 버튼으로 Admin에 들어가는 흐름으로 통일.
  (이미 로그인된 상태에서 이 링크를 다시 눌러도 Django Admin이 자체적으로
  대시보드를 보여주는 동작이라 문제 없음 — 어차피 로그인 후엔 헤더의 편집
  버튼을 주로 쓰게 됨.)

### 프로젝트 목록에 커버 이미지 썸네일 추가

  `Project.cover_image` 썸네일(96×72px, 모바일 64×48px)을 번호와 제목 사이에 추가.
  커버 이미지가 없는 프로젝트는 점선 테두리 placeholder 박스로 표시해 레이아웃
  붕괴 없이 자연스럽게 처리.
- 작업 중 커버 이미지 렌더링 검증을 위해 임시 테스트 이미지를 특정 프로젝트에
  넣었다가 "원상복구"한다며 지웠는데, 알고 보니 사용자가 이미 넣어둔 실제
  사진이었던 사고가 있었음 — 이후 실제 데이터가 있는 레코드에는 임의로 테스트
  값을 넣고 지우지 않기로 함 (별도 테스트용 더미 레코드를 쓰거나 먼저 확인).

### 프로젝트 목록에 기간 표시 추가
- 홈 "대표 프로젝트"와 `/projects/` 전체 목록에, 상세 페이지와 동일한 포맷
  (`YYYY.MM — YYYY.MM`, 진행 중이면 "진행중")으로 프로젝트 기간을 태그 형태로 추가.
  전체 목록에서는 기술 스택 태그들과 나란히 표시하되, 기간 태그만 포인트 색으로
  구분해 한눈에 들어오도록 함.

### 확인한 사항
- 로그인 → 사이트 홈으로 리다이렉트되는 것 확인 (Admin 대시보드로 안 넘어감).
- 커버 이미지가 있는/없는 프로젝트 각각에서 썸네일·placeholder가 올바르게 렌더링되는 것 확인.
- 홈/전체 목록 양쪽에서 기간 텍스트가 정상 표시되는 것 확인.
